TripFlow Desktop版 v0.6まで完成。
Web v0.1・Web v0.2・Web v0.3完成。

- Phase E-1：`gmail_message_id`／`gmail_thread_id`／`source_type`／`reservation_key`の4列を`reservations`テーブルへ追加（土台。UNIQUE制約は付けない設計）
- Phase E-2：TARGET判定メールの解析結果をユーザーが確認したうえで「TripFlowに登録」ボタンを押した場合のみDB保存する機能を実装（自動登録はしない）
- Phase E-3：`gmail_message_id`の完全一致による同一メールからの二重登録防止（DB照合を正本、session_stateは補助、画面表示時＋登録直前の二重チェック）
- Phase E-4：予約日（交通は乗車日、ホテルはチェックイン日）とTrip期間の自動マッチング（期間外のTripは登録先候補から除外、一致0件なら登録不可）

Web v0.4 Phase F-1：v1.0（ローカル版）に向けた安全性強化として、ユーザー分離のDB層回帰テスト追加・`get_reservation_status()`のDB読み取りエラー保護を**完了・commit / push済み**。

現在はPhase F-2（README・design.md・roadmap.mdのドキュメント現行化、開発用CSVファイルの管理方法整理）に着手している。
